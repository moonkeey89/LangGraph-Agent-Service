1、Agent通过LLM进行任务理解和决策，开发者将Python函数封装成Skill，
    并通过Tool描述暴露给LLM。LLM根据用户任务选择合适Tool，Agent运
    行时负责执行对应Skill，并将执行结果反馈给LLM完成最终响应。
    Agent目的是将复杂目标拆解成多个可执行子任务，并协调不同能力完成目标
2、Agent 是一种基于大语言模型的任务执行系统，通过 LLM 进行任务理解
    和规划，通过 Tool Calling 调用外部 Skill 完成具体操作，并根据
    执行结果继续推理，最终完成复杂任务。Skill=真正干活的Python函数；Tool=给LLM看的接口描述

3、Agent 第一次接收用户请求时，程序会将当前可用的 Skills（Tools）的名称、功能描述以及参数格
    式，通过 Tool Calling 接口一起发送给大语言模型。LLM 并不知道 Python 中真实存在的函数，而是根
    据这些工具描述和用户需求进行语义判断，选择最合适的工具并生成调用参数。随后由程序真正执行对应 Skill，
    并将执行结果重新反馈给 LLM，形成 Reasoning → Action → Observation 的 ReAct 循环。

4、State就是记录Agent当前“脑中所有重要信息”的数据结构。实际上就是一个 Agent 的“短期工作记忆”，Memory = 人的大脑记忆
    State = 人当前桌面上的工作资料，类似一种进度管理。State不是简单的数据保存，而是Agent所有节点之间共享的“动态上下文”。
    LangGraph通过State连接不同Node，让Agent能够根据当前状态动态决定下一步行动。这也是从普通LLM应用走向真正Agent系统的关键一步。

5、“如何避免 Agent 陷入无限循环？”State记录执行状态
                                retry次数限制
                                error记录
                                conditional routing
                                fallback策略
                                human intervention

6、State 是 Agent 的核心数据载体，记录智能体当前所处的环境和任务信息；Node 是改变 State 的执行模块，
    负责完成具体能力；Edge 是连接 Node 的控制规则，决定 State 下一步流向哪里；return state 则保证每
    一次 Node 执行后的状态变化能够继续传递。四者结合后，Agent 就从简单的“输入问题→输出答案”的模型调用，
    变成了一个能够规划、执行、观察结果并根据状态调整行为的动态系统。这也是 LangGraph 设计 Agent 工作流
    的核心思想。

7、Router 决定“走哪条路”，Planner 决定“具体怎么做”，Executor 负责“真正执行”。

8、LLM负责：理解任务、推理、决策、生成回答。
Tool / Skill负责：把确定性任务交给程序执行。
Tool Calling负责：让 LLM 决定什么时候调用git 哪个 Tool，以及传递什么参数。
Planner负责：把复杂任务分解成执行步骤。
Executor负责：真正执行这些步骤。
State负责：在 Agent Workflow 中保存任务状态。
Router负责：控制不同任务进入不同工作流。
Memory负责：保存跨轮次有价值的信息。
Graph负责：描述 Agent 的执行流程和循环。
